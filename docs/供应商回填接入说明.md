# 供应商入库回填接入说明

本文说明「采购入库 → 按 ICCID 向上游供应商拉取卡信息 → 回填本地卡档案」的实现、配置和验收步骤。首期只实现中国移动 CTBOSS（`cmcc-ctboss`）适配器，所有查询均为只读。

## 1. 能力范围

- 采购入库保存时登记回填任务，入库单、卡记录和任务在同一数据库事务内提交；供应商 HTTP 调用不在事务内。
- 回填字段：MSISDN、IMSI、IMEI、首次激活日、运营商资费失效日、资费名称、APN、开通功能、周期用量。
- 只覆盖本地空值，已有的人工数据不会被供应商返回值覆盖。
- 支持手工单卡对账、失败重试、批量重试，以及历史卡补拉。
- 不包含：自动发现供应商侧的全部卡、开卡/激活/停卡/销卡、供应商账单核对。

## 2. 数据流

1. 采购入库校验 ICCID 后写入 `sim_card`、`card_location`、`sim_plan`。
2. 同一事务写入 `carrier_sync_queue(iccid, requested_by, operation='IDENTITY', request_id=UUID())`。
3. `CarrierSync` 每 3 秒取一条到期任务，用 `lease_token + lease_until` 加租约，避免多个实例重复处理。
4. `SupplierRouter` 按 `carrier_account.adapter_key` 选择 `CardInfoProvider`，`SupplierCredentials` 从环境变量读取账号密码；同一账号的令牌缓存 60 秒，避免批量入库时重复申请。
5. 供应商返回后开启短事务：校验卡仍属于同一账号，回填 `sim_card`，写入 `carrier_snapshot`、`carrier_services`、`group_usage`/池用量，并记录 `sim_event`。
6. 按结果更新任务状态；可重试错误按指数退避重新排队。

## 3. 数据库变更

合并版本统一执行 `python3 database/migrate.py --user root`，供应商扩展在商品分类之后执行。底层 `database/06-supplier-inbound.sql` 可重复执行，只增加缺失列和索引，保留既有账号配置与任务状态。

| 表 | 新增内容 | 用途 |
| --- | --- | --- |
| `sim_card` | `imsi`、`last_reconciled_at`、索引 `idx_card_carrier` | 保存 IMSI 和最近回填时间 |
| `carrier_account` | `supplier_type`、`api_category`、`api_sub_category`、`adapter_key`、`api_url`、`config_json` | 供应商路由和非敏感配置 |
| `carrier_sync_queue` | `operation`、`request_id`、`lease_until`、`last_error`、`error_class`、`completed_at`、`updated_at`、索引 `idx_sync_status` | 租约、重试和排障 |

`config_json` 只允许放非敏感配置，账号密码不得写入数据库。

## 4. 账号与凭据配置

在「系统管理 → 运营商接口配置」新增或编辑账号：

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| 名称 | 中国移动 · 演示集团 | 页面显示名 |
| 环境凭据标识 | `GD_01` | 只允许大写字母、数字和下划线 |
| 供应商类型 | `CMCC` | 同时作为环境变量前缀 |
| 接口大类 | `CMCC` | 供应商产品线 |
| 接口子类 | `CMCC_CTBOSS` | 接口版本标识 |
| 适配器标识 | `cmcc-ctboss` | 必须与代码中的 `adapterKey()` 一致 |
| 接口地址 | 留空或 `https://api.iot.10086.cn` | 留空使用官方地址；本地联调可指向模拟服务 |
| 启用供应商回填 | 开 | 关闭后该账号下的卡不会被调度 |

后端启动前设置环境变量，命名规则为 `<供应商类型>_<凭据标识>_APPID` 和 `<供应商类型>_<凭据标识>_PASSWORD`：

```bash
export CMCC_GD_01_APPID='REPLACE_WITH_APPID'
export CMCC_GD_01_PASSWORD='REPLACE_WITH_PASSWORD'
```

密码只存在进程环境中，不会出现在接口响应、日志或数据库里。缺少凭据时任务直接进入永久失败，补齐环境变量后可在页面点「重试」。

## 5. 页面操作

入口：「仓库管理 → 供应商回填」。

- **统计卡片**：回填任务总数、等待中、已完成、需要处理、缺卡号/IMSI 的卡数。
- **状态筛选**：排队中、查询中、已完成、部分回填、等待重试、已失败、永久失败。
- **单卡重试**：把该 ICCID 的任务重置为排队，立即重新执行。
- **重试全部失败**：批量重置失败任务，返回受影响条数。
- **补拉缺卡号/IMSI**：把缺少 MSISDN、IMSI 或从未回填、且所属账号已启用的卡重新排队；返回本次选中的卡数。
- **列表字段**：ICCID、采购单、商品、供应商账号、适配器、状态、尝试次数、卡号、IMSI、IMEI、最近回填、最后错误。

采购入库弹窗中已提示「保存后自动向上游查询卡信息」，无需人工逐张点对账。

## 6. 状态与重试

| 状态 | 含义 | 后续动作 |
| --- | --- | --- |
| `QUEUED` | 已排队，等待调度 | 自动执行 |
| `RUNNING` | 已加租约，正在调用供应商 | 租约过期后可被重新领取 |
| `SUCCEEDED` | 必填字段全部返回 | 无 |
| `PARTIAL` | 主查询成功，部分可选字段缺失 | 可重试，或等供应商数据补齐 |
| `RETRYABLE_FAILED` | 超时、网络、5xx、限流等 | 按 5/10/20/40 分钟退避，最多 5 次 |
| `FAILED` | 可重试错误达到次数上限 | 人工排查后重试 |
| `PERMANENT_FAILED` | ICCID 不符、账号停用、参数或配置错误 | 修正配置或数据后重试 |

任务主键为 ICCID，同一张卡同一时刻只保留一个待执行操作。首期只有 `IDENTITY`，后续增加多操作时需要把队列主键改为代理键。

## 7. 新增供应商适配器

1. 实现 `CardInfoProvider`，提供 `adapterKey()`、`open()`、`fetch()`、`call()`、`optional()`。
2. 供应商特有的签名、分页和字段映射放在适配器内部；通用回填、重试和页面不需要修改。
3. 在账号上填写相同的 `adapter_key`，启用后即可路由。
4. 对外部错误使用 `SupplierFailure.retryable/permanent/config` 分类，避免把参数错误当成网络错误反复重试。

## 8. 已验证内容

- 后端 `mvn test`：11 个测试全部通过，覆盖 CTBOSS 字段解析、适配器路由和失败分类/退避。
- 前端 `npm run build`：类型检查和构建通过。
- 本地模拟供应商端到端：采购入库排队 → 调度 → 回填卡号、IMSI、IMEI、激活日、到期日和资费，任务为 `SUCCEEDED`。
- 全新数据库按 `01 → 02 → 03 → 06` 初始化成功；`06` 连续执行两次无报错。
- 登录后接口冒烟：`/api/erp/supplier/summary`、`/queue`、`/retry-failed`、`/backfill` 和 `/api/admin/carriers` 均正常；缺少凭据时测试接口返回 400 和明确错误码。
- 以上验证全部使用本机 MySQL 和本地模拟服务，没有连接线上数据库，也没有调用供应商生产接口。
