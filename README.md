# 云枢 ERP

面向物联网卡和设备业务的内部 ERP 与客户自助门户。前端使用 Vue 3、TypeScript、Element Plus，后端使用 Java 21、Spring Boot、Spring Security 和 JDBC，数据保存在 MySQL。ERP 管理后台和客户门户使用独立页面地址与登录表单。后端校验入口对应的账号角色、客户归属和审批节点。

## 在 Mac 上启动

压缩包的顶层目录是 `GPTCODE/`。在 Finder 中把它解压到目标父目录 `liu/YSERP/`。以下命令都从解压后的 `GPTCODE` 目录开始。依赖为 JDK 21、Maven 3.9、Node.js 22.12 或以上兼容版本和 MySQL 8.4。

**数据库安装与升级**，统一使用 Python 3 迁移入口。先备份业务库并停止后端写入，使用具备建库、建表、创建存储过程及触发器权限的 MySQL 管理账号执行。认证沿用 mysql 的本机默认配置（`~/.my.cnf` / `~/.mylogin.cnf`），也可通过 `MYSQL_PWD` 环境变量提供；脚本不会输出密码。

```bash
# 只读检查迁移计划
python3 database/migrate.py --user root --check
# 升级已有 yunshu 库，保留现有账号、密码与业务记录
python3 database/migrate.py --user root
# 新建含演示基础资料的空库（仅新装时使用）
# python3 database/migrate.py --user root --demo
```

可用 `--database`、`--host`、`--port` 指定目标。默认不导入演示数据，`--demo` 在已有业务库上会拒绝执行。不要按文件名前缀排序逐个运行 SQL：两边的 05、06 脚本用途不同，部分脚本只能执行一次。迁移入口按依赖执行，使用 `schema_migration` 记录校验和与完成状态，支持接管已完整升级的 GitHub 版本。遇到部分升级或上次中断会停止；MySQL DDL 不会自动回滚，须核查错误并从备份恢复后重试。执行过编码规则后，旧 `05-upgrade.sql` 会拒绝运行，防止重建旧门户视图。

商品分类迁移保留原分类和商品 ID，按原名称回填父子关系、商品归属和引用次数。已有未分类商品以及曾关联一级、二级或停用分类的商品仍可查看，下次编辑保存时须选择启用的三级分类。若旧名称有歧义、上级无效、层级超过三级或存在循环，迁移会列出问题记录并停止。修复前须核查迁移记录；对于同名目标，可在升级前将旧字段（`master_profile.details` 中的 `parent` / `category`，或已迁移库的 `base_reference.parent` / `sku.category`）改为 `@code:目标分类编码`。

迁移顺序、核验结果见 [合并与迁移核验](docs/合并与迁移核验.md)。数据库回归测试会创建并清理随机名称的临时库：`MYSQL_TEST_USER=root python3 database/test_migrations.py`。

在 MySQL 中给运行应用的本机账号授予业务库读写权限。下面使用占位密码。

```sql
CREATE USER 'yunshu'@'localhost' IDENTIFIED BY 'REPLACE_WITH_DB_PASSWORD';
GRANT SELECT, INSERT, UPDATE, DELETE ON yunshu.* TO 'yunshu'@'localhost';
```

**启动后端**，新开一个终端窗口。

```bash
cd backend
export DB_USER=yunshu
export DB_PASSWORD='REPLACE_WITH_DB_PASSWORD'
export ERP_DEMO_PASSWORD='REPLACE_WITH_LOCAL_DEMO_PASSWORD'
export ERP_PDF_FONT='/absolute/path/to/ChineseFont.ttf'
mvn spring-boot:run
```

首次本地试跑将 `ERP_DEMO_PASSWORD` 改为自己选择的至少 12 位密码。此设置创建 `admin`（管理员）、`buyer`（内部采购人员）、`customer`（演示客户）。只有本地演示账号共用该初始密码。已存在的账户保留原密码，后续启动可移除此变量。默认数据库地址为 `127.0.0.1:3306/yunshu`，自定义连接可设置 `DB_URL`。中文 PDF 需要含中文字形的字体文件；TTC 字体使用带字库编号的绝对路径，例如 `/absolute/path/to/font.ttc,0`。

**启动前端**，在另一个终端从项目根目录运行。

```bash
cd frontend
npm ci
npm run dev
```

| 访问对象 | 本地登录入口 | 登录后可访问 |
| --- | --- | --- |
| 内部员工 | `http://localhost:5173/erp/login` | 工作台、业务单据和本角色获准的配置页 |
| 客户 | `http://localhost:5173/portal/login` | `/portal/orders` 我的订单、`/portal/cards` 我的流量卡、`/portal/inquiries` 订购申请 |

根路径展示入口选择。收藏详情地址后可直接登录并回到原页。旧的 `/#/sales_order_list` 等 ERP 链接会跳至对应的新地址。同一浏览器会话使用一个账号，跨入口访问时可返回当前账号的工作区或切换账号。

开发代理把 `/api` 转发至本机 8080。前端执行 `npm run build`，后端执行 `mvn clean package`。生产环境将 `frontend/dist` 部署在网站根目录。Web 服务器应将 `/erp/`、`/portal/` 下的前端页面请求回退至 `/index.html`，静态资源按实际文件返回，`/api/` 单独反向代理至 Spring Boot。两端使用同源会话及 CSRF 令牌。

**可选演示业务数据**。执行 02 已可使用演示客户、供应商、商品、移动集团账号及打印模板。想直接看到两张有行明细的订单，在后端首次启动并创建演示账号后执行下列命令。它创建一张采购草稿和一张销售草稿，可以重复执行，不产生期初库存。该脚本不是数据库结构升级脚本，旧库升级请使用上面的 `migrate.py`。

```bash
mysql -u root -p < database/04-demo-orders.sql
```

## 商品分类

在「基础档案 → 商品分类」新建一级分类时留空上级，建立二、三级分类时选择上级。商品创建或编辑时按完整路径选择启用的三级分类。列表显示层级和引用次数，一次直接关联计一次。商品换分类或子分类改上级时，旧分类减一，新分类加一。原分类不变的重复保存不会重复计数。

分类列表及详情页可删除分类。只要存在直接子分类、直接关联商品或正数引用，后端会拒绝删除。商品列表和详情同样提供删除入口，已有单据或库存记录的商品由关联约束保护。

## 编码规则

在「基础档案 → 编码规则」点击单据类型即可编辑。规则沿用内部基础档案的维护权限。弹窗按当前日期和初始值实时预览，例如客户启用日期、长度 3、初始值 001，在 2026 年 11 月 23 日的预览为 `CU261123001`。打开、预览、保存规则或取消都不会占用号码。

业务档案或草稿首次成功保存时分配编码。带日期的类型以北京时间的创建日期分组并每日重新起号，无日期的类型连续编号。切换日期选项后再次切回会接续原序列。初始值是下次发号的下限，调低初始值不会复用旧号码。流水号达到当前位数的上限时，本次新增会回滚并提示扩大位数。规则调整、编辑草稿、改业务日期或驳回重提均保留已保存编码。

## 第一次验收

1. 用 `admin` 进入「订单管理 → 采购订单」。新建采购单或打开演示草稿，选择客户套餐对应的卡商品、供应商、移动集团账号、收货仓库和到货日。保存后先下载 PDF，再提交、审核。
2. 在已审核采购单上点「生成采购入库单」，向每行录入 ICCID。终端卡可逐张指定集团账号、独立额度、激活日、套餐名称及周期。保存、提交、审核入库后检查库存和采购卡号明细。设备只填写数量。
3. 用独立浏览器窗口登录 `customer`，提交一笔订购申请。回到 ERP 的「系统管理 → 客户订购申请」确认转单。销售订单以草稿落库。补全交期、审核并出库，流量卡逐张选择并填写 ERP 有效期。
4. 在客户门户查看自己的订单、用量及有效期。在 ERP「客户可见字段」取消勾选某一列，再刷新门户，可验证服务端实际裁剪。门户展示商品的对客名称，可在商品档案维护。
5. 在「流量卡查询与对账」打开已交付卡，核查移动返回日期、ERP 日期、用量快照和套餐周期。对有采购权限的终端卡设置当前周期人工修正，再撤销，核对客户展示。若缺少真实移动凭据，仍可验证周期、人工修正、权限及内部续期。
6. 从原卡打开「新建换货出库」或「新建退货入库」，保存并提交。审核前客户仍可查旧卡。审核后客户失去旧卡权限，换货时新卡出现在同一客户门户。
7. 验证审批配置时，给采购订单设置两个节点，第一个节点同时指派 `admin` 和 `buyer`。任一人通过即可进入第二节点。制单人在获指派节点可自审，驳回后从草稿重新提交。

## 中国移动 CT

「运营商接口配置」按地方移动集团账号保存名称、凭据标识和启用状态。集团账号与卡类别独立。同商品在不同批次、同一批次的不同 ICCID 都可使用不同的集团账号。假设配置的凭据标识为 `GD_01`，后端环境配置如下。

```bash
export CMCC_GD_01_APPID='REPLACE_WITH_APPID'
export CMCC_GD_01_PASSWORD='REPLACE_WITH_PASSWORD'
```

配置后重启后端并测试认证。采购入库会登记待查询卡，后台对已启用的账号取数。ERP 可立即手动对账；客户可在门户点击「更新用量」，随后刷新列表。后台失败会有限重试，最近一次成功读取的数据保持可用。上线前需由持有移动集团生产账号的一方核对账号归属、接口订购、出口 IP 白名单和实际字段返回。

集团卡使用移动资费、套餐用量和开通业务，终端卡使用池内单卡用量与内部套餐。运营商按自然月计数，客户套餐可从月中激活或交付之日起计算。有效计算起点取交付日和激活日较晚者；不能由现有读数精确分摊时，采购人员在「跨月或首期用量基线」登记本月计数器基线和此前归属该套餐周期的累计用量，再查移动即可折算。未核对的数据展示为空。人工修正只在指定套餐周期生效。销售续期只修改 ERP 有效期，运营商资费失效日独立留存供核对。


## 供应商入库回填

采购入库保存时，每张 ICCID 会同时写入一条 `carrier_sync_queue` 任务（`operation=IDENTITY`），与入库单在同一事务内提交。后台调度器按 `adapter_key` 选择供应商适配器，在数据库事务之外调用供应商接口，成功后再用一个短事务回填卡号、IMSI、IMEI、激活日、到期日和用量，并写入 `carrier_snapshot`、`carrier_services`。接口超时、限流和 5xx 会按 5、10、20、40 分钟退避重试，最多 5 次；ICCID 不符、账号停用、参数错误等直接标记为永久失败。

- 入口：「仓库管理 → 供应商回填」。可查看任务状态、卡号/IMSI/IMEI 和最后错误，支持单卡重试、批量重试失败，以及把缺少卡号/IMSI 或从未回填的卡重新排队。
- 字段规则：只覆盖空值，不覆盖本地人工维护的卡号、IMEI、激活日和到期日；供应商未返回的可选字段记入 `unavailable`，任务状态为「部分回填」。
- 账号配置：「系统管理 → 运营商接口配置」维护供应商类型、接口大类/子类、适配器标识和接口地址。当前内置适配器为 `cmcc-ctboss`，接口地址留空时使用中国移动官方地址；测试和本地联调可填写本地模拟服务地址。
- 安全边界：供应商密码不落库，只从环境变量读取；排队任务只读取供应商卡信息，不执行激活、停卡、销卡等写操作。

新增供应商时，实现 `CardInfoProvider` 并声明新的 `adapterKey()`，在账号上填写同名 `adapter_key` 即可，无需改动入库逻辑。字段含义和联调步骤见 [供应商回填接入说明](docs/供应商回填接入说明.md)。

页面、接口、数据库表的对应关系、验证范围及当前业务边界详见 [功能验收对照](docs/功能验收对照.md)。
